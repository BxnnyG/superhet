# Security policy

## Supported versions

Superhet is pre-alpha. Only the latest commit on `main` receives fixes.

## Reporting a vulnerability

Please **do not open a public issue**. Use GitHub's private vulnerability reporting ("Security" tab → "Report a vulnerability") of this repository. You will get an acknowledgement within 7 days.

## Scope and hardening principles

- Only `superhet-api` is exposed to the network; all other services (sdrd, pluginhost, worker, PostgreSQL, NATS) are on an internal network.
- Every service has its own NATS user with subject permissions and its own PostgreSQL role with minimal privileges.
- Secrets live in `.env` (generated by `scripts/gen-secrets.sh`) and are never committed; CI runs gitleaks on every push.
- Dependencies are checked with `cargo deny` (advisories, licenses) and Dependabot.
- No Docker socket is mounted into any container. Plugins are third-party code: installing one means trusting it; the UI shows manifest, build commands and license before installation.

## Repository hygiene

No personal data (addresses, phone numbers, locations of stations, real ISSIs/talkgroups of private networks, credentials) in code, docs, test fixtures or commit metadata. Reference recordings used as test fixtures must be reviewed for such data before they are committed.
